Compatibility entry-point checkpoint, 2026-10-24
------------------------------------------------
Exports feols(fml,data,...) and feglm(fml,data,family="gaussian",...), with named
conn/table/path inputs following native conventions. Genuine native model classes
inherit dbreg_fixest; no fake fixest fit class or fixest Imports dependency.
Unknown/unsupported statistical arguments error. Supported simple column formulas
and positional R weights/offset vectors normalize before filtering; SQL vectors
are rejected. Restricted subset predicates and recursive OLS singleton removal
share native helpers. Original R positions and typed SQL identities precede all
filters. Positive R subset indices must be unique/increasing; negative exclusions
are supported. Duplicate/reordered subsets and non-column weight/offset formulas
are explicitly unsupported. Vector offsets require an explicit newdata offset.

Native retain="inference" saves row/score state without learned-effect recovery.
Adapters use it transiently for lean=TRUE, then release rows/dictionaries. Cached
likelihood/covariance remain portable. Full retention is the adapter default,
including learned effects; native compact defaults remain unchanged. Ordinary OLS
keeps current strategies; factor-coercion/varying-slope/intercept-only OLS uses the
shared Gaussian projector with OLS reporting. Linear models support fit-time and
post-fit two-way covariance; nonlinear GLMs one-way. Native fit-time dbreg/dbglm
clustering remains one-way; adapter two-way fitting uses the retained engine.

Fit-time clusters contribute missing-value exclusions before estimation; later
cluster requests use the immutable fitted rows and error on missing values.
Wrapper SSC defaults use the fixest nonnested policy; later summary requests
inherit their selected policy. Model K, covariance K and testing df stay distinct.
Response is the adapter prediction default. feols logLik and AIC/BIC deliberately
use fixest's differing likelihood-df/model-penalty conventions. Cached lean OLS
likelihood and NoFE newdata prediction remain available, even where the pinned
reference's lean methods lose data. Native methods keep native conventions.

Own coeftable/se/pvalue/tstat/ssc/degrees_freedom and coefficient selectors cover
supported extraction. Delayed S3 registrations also support fixest extraction
generics, with both namespace-load orders checked. fixest::obs/degrees_freedom
are not generic: use dbreg's versions. Extracted vectors consistently carry public
names; comparisons ignore incidental reference vcov_type attributes. Some pinned
Gaussian reference coeftables are data.frames. Reference fitting is independently
refined from fixest's own estimates. In one small weighted cloglog case, native
raw score is about 2.5e-8 while reference is about 2.1e-5; coefficients differ by
about 5.9e-7, within the explicit absolute 1e-6 gate. No production solver was changed
to match a less accurate reference stop.
