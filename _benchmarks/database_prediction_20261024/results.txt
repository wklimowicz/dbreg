Implemented behavior and boundaries
-----------------------------------
retain="prediction" preserves compact native defaults unless explicitly chosen.
If portable recovery exceeds its limits, a single absorbed FE without varying
slopes can keep an owned typed dictionary in SQL. Composite FE keys are one
block and may combine exact integer, nearby-double, character, date/logical keys.
Original fitted slopes stay fixed. Weighted residual means recover group
effects; a bounded within-X Gram/null system checks new-row estimability.
Recovery must reproduce the fitted eta or OLS RSS. Matching queries only the
requested rows in bounded batches. Outcomes/weights/source tables are not needed
after fitting. Unknown/missing keys and nonestimable rows return NA.

Small dictionaries remain portable. Database dictionaries require their live
owning session; deserialized/disconnected handles error before SQL and never
reconnect, refit, or reread mutable caller data. Mathematical state stays in
plain values; a separate versioned lease owns only specified relations.
close(model) is idempotent, preserves caller connections/exports, shares release
across model copies, and closes an owned connection after its last lease.
Namespace finalizers avoid capturing fitting frames. Failed drops remain tracked
and retryable; successful drops are not repeated against reused table names.

Tests cover demean/compress OLS, binomial/Poisson GLMs and offsets, reference
predictions and full covariance, sample exports, batching/order, BIGINT and
composite keys, arbitrary text/dates/logicals, collinearity/absorbed regressors,
serialization, source removal, cleanup, owned/borrowed sessions, output-lease
lifetime, finalization, invalid handles and a real foreign-key drop failure.
Large multi-FE/varying-slope dictionaries, keyed database prediction output,
original-sample/default predictions and retained post-fit inference are pending.
Output resource sharing is tested internally; no database output API is exposed.

Large-state local measurement
-----------------------------
large-state.R creates a deterministic SQL-only million-row panel with 400,000
FE levels and four slopes. The default prediction entry budget is 2e6, so this
selects SQL state without reducing a limit artificially. Six completed measured
fits (three per mode, after one warmup each) match named coefficients, full
covariance and N. Retained predictions match an independent SQL group-mean
identity, and closing every fit restores the initial table inventory.

                   compact default      retained prediction
median fit         0.243s               1.154s
peak process RSS   491,580 KiB          635,440 KiB
mathematical state 0 bytes              5,792 bytes

The optional path added about 0.91s and 29% whole-process peak RSS here. DuckDB
is embedded, so RSS includes database execution memory; it is not isolated R
heap usage. The 400,000-row dictionary stays in SQL. Instrumented prediction
recovery queries return at most one row during fitting, with 7,272 cumulative
R result-object bytes (object.size, not protocol transfer bytes). Only 100
newdata rows are fetched for prediction checks, outside fit timing. No panel
is collected into R. Source metadata and traces identify the measured scope.

R 4.6.0, DuckDB 1.5.2; two DuckDB/BLAS/OMP threads, 2GB DuckDB memory limit.
These are warmed local resource measurements with timing variation and a local
test/native-validation client active in the background, not precise latency or
native/disk-bound guarantees. Default fitting was already compared against the
pre-compatibility baseline in the separate 90-fit linear checkpoint.
