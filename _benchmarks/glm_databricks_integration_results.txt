Databricks GLM production integration and validation
2026-10-23

This records the first production integration. The subsequent exact pruning
optimization and its measurements are in glm_databricks_followup_results.txt.
The source checksum and validation counts below describe that earlier snapshot.

The optimized path is now part of dbglm(), selected automatically for eligible
Databricks models. The normal formula and convergence tolerances are unchanged.
This is a backend-specific SQL generator feeding the shared estimator, not a
separate statistical implementation or a benchmark namespace substitution.

What changed

1. R/glm-databricks.R generates three aggregation branches: globals,
   GROUPING SETS for FE marginals, and weight-only GROUPING SETS for FE pairs.
   DuckDB keeps its materialized shared-source aggregation. Existing exact
   score/deviance sum safeguards remain in use on Databricks.

2. Small dense categorical FE coefficient dictionaries use constant arrays
   instead of repeated broadcast lookup joins. Positive integer ranks,
   density, total entries and SQL bytes are bounded. Oversized/sparse
   dictionaries use the existing join path. The automatic array path is
   limited to additive categorical FEs; varying slopes retain their joins.

3. Expanded FE-model regressors are centered before projection moments.
   Subtracting constants preserves slope units, estimates and covariance
   because the FE space already contains the constant. This improves Schur
   subtraction conditioning and eliminates the observed uncentered stall.
   Centers are recorded in design_center. No-FE models are unchanged.

4. The initial FE moment query has a transfer cap plus an overflow sentinel.
   Overflow falls back to complete scalar diagnostics; truncated moments
   cannot certify convergence. The fit owns an immutable physical base
   snapshot, and IRLS changes values rather than rows or FE keys. Its verified
   support count can therefore be reused without sorting every evaluation.
   Any unexpected support-cardinality change errors. Tests cover unknown,
   sufficient, insufficient and changed bounds, including absent global rows.

5. Global summaries travel in one JSON payload and stay in a separate one-row
   object in R. They are not expanded into mostly-NULL columns on every pair
   row. This matters particularly when the number of global second moments
   grows quadratically with the number of regressors. Transfer limits bound
   rows/FE coefficient entries, not every possible model's total RAM use.

6. Every successful recursive-pruning round materializes its reduced sample.
   This prevents exponentially nested SQL on Databricks. The common case with
   no pruning adds no write, and the moments path still avoids N-row state
   writes during IRLS. New-row FE prediction remains unsupported, as documented.

7. Verbose diagnostics now show the profiled score when the final certificate
   rejects an apparently converged iteration. Documentation was updated to
   describe the actual execution path and centering; existing stale argument
   signatures found by R CMD check were regenerated. No new Imports were
   added; odbc is an optional test dependency in Suggests.

Where the time now goes

The seven production evaluation queries together take 59.618 / 58.572 s.
Their server compilation totals are 4.173 / 4.200 s (original about 108 s);
execution totals 31.100 / 30.770 s; result-fetch totals 22.694 / 21.276 s.
Setup/cleanup costs 24.392 / 24.339 s and covariance 4.833 / 4.737 s.
Server counters are not an additive decomposition of client wall time.
Further gains would target setup and sparse-result transport; the small local
Schur solver is not the main remaining cost. No further runtime is promised.

Rejected experiments retained

The original uncentered array-only prototype stalled at the final score
certificate and was interrupted. The integrated path centers automatically.
Adding an ordered limit to every evaluation passed numerical checks but cost
100.316 / 105.106 s per Databricks fit. Removing ordering from the preflight
then produced a roughly 308 s client fetch for a query that completed on the
server in about 3.4 s; that run was interrupted, not counted as a successful
fit. Its underlying driver/transport cause was not established. The final
implementation retains ordered preflight and reuses its fixed support bound.

Validation design

Independent references are glm/lm and fixest; the strict small-model helper
refines fixest using only fixest's own previous linear predictor. It never
starts the oracle from dbglm estimates. Comparisons include full covariance
matrices, SEs, likelihood, sample size, coefficient names, FE degrees of
freedom and convergence, not just one headline coefficient.

Existing coverage includes no/one/two/six FEs, logit/cloglog/probit/Poisson,
offsets, integer weights, IID/HC1/cluster covariance, varying slopes, absorbed
columns, interactions (including 88 slopes), scaling, boundaries, missing
values, pruning, solver fallbacks and cleanup. The Databricks SQL fixture is
explicitly an offline portability test, not a substitute for Spark execution.

New cases run through that fixture and on the live warehouse: six correlated
FEs with multiple regressors; all four families and three covariance types;
array/join equivalence; a 1e6 regressor shift; rank holes and sparse-rank/byte
fallbacks; scalar serialization over extreme magnitudes; bounded overflow
and fixed-support reuse; exact retained-row IDs after exclusions and recursive
pruning; df parity and cleanup after a rejected fit. Live result reuse is off.

Final validation results

The final source passed R CMD check with 0 errors, 0 warnings and one NOTE:
the optional binsreg package was unavailable for an Rd cross-reference.
The package check ran 2,088 assertions across 29 nonempty test files. Five
files were skipped/empty: three NYC-data suites, the optional binsreg
comparison, and the environment-gated live Databricks suite. The latter
was run separately against the actual warehouse and passed all 209
assertions; the separate live sample/pruning suite passed all 14 assertions.
Thus 223 native Databricks assertions passed on the final source. The
offline sample/pruning run is also included in the package-check count.

Evidence is retained in glm_databricks_integration_check.log,
glm_databricks_integration_test_counts.csv and
glm_databricks_integration_live_final.csv. The source checksum manifest is
glm_databricks_integration_source.sha256. Production fit and query records
are teacher_cloglog_production_fits.csv and
teacher_cloglog_production_queries.csv; all recorded production statements
finished successfully and none reused the query result cache.

Live tests require the already configured native ODBC driver and Databricks
environment credentials. They use only synthetic session-temporary tables.
The original benchmark report explains regeneration of the 5M sample/oracle.

These results support using the implementation for the documented GLM scope,
especially the tested teacher-shaped additive-FE cloglog model. They do not
prove every possible data/design combination safe or constitute a complete
general separation detector. Unsupported cases and failed convergence remain
explicit errors rather than ordinary successful inference.
