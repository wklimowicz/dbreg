Scope and changes
-----------------
All new fixtures and warehouse work use synthetic data. This follow-up adds
seeded rare-outcome stress tests, known-separation cases with analytic finite
controls, an 88-slope teacher design, shared value/sample assertions, a native
CI runner, and reproducible larger validation scripts. Existing historical
performance reports remain unchanged; this work does not establish a new
performance frontier.

Three concrete correctness problems surfaced during validation:

1. Large Databricks coefficient literals exhausted the SQL tokenizer's PCRE
   match limit. The original 7,200,024-byte reproducer was truncated to 14
   bytes. The fixed translator consumes quoted runs without per-character
   backtracking, preserves quoted identifiers/literals, and rejects incomplete
   tokenization. A 7.2 MB regression now runs locally and on native Databricks.
   Evidence: glm_research_validation_sql_literal.csv and
   glm_research_validation_native_literal.csv.

2. Once tokenization preserved the complete statement, the 5M fit converged
   but its clustered-covariance request exceeded the warehouse query-text
   limit: it repeated the full coefficient dictionary once per FE. A shared
   CTE now defines that dictionary once, with per-operation filtered CTEs.
   Both predictor and projected-score construction use the same helper.
   The regression case has 2,400 FE dictionary rows and 88 coefficient columns;
   it checks the request bound and actual aggregate values on local/native SQL.
   Evidence: glm_research_validation_lookup_size.csv and native suite results.

3. On this DuckDB version, bigint="numeric" imports R integer64 storage bits
   as floating-point values. Automatically managed connections now preserve
   integer64 inputs. Supplied connections must preserve their SQL BIGINT type
   or estimation fails with a clear corrective message. Setup releases owned
   registrations/connections on failure. Prediction also decodes numeric
   integer64 regressors/offsets after preserving exact factor levels.
   test_integer64_input.R checks OLS/GLM parity, adjacent FE and row keys above
   2^53, exported IDs, frequency weights, predictions and failure cleanup.

The integer64 defect also invalidated the first local export of the large
synthetic input: corrupted IDs removed the intended teacher-wage innovation.
Those reference/local attempts are discarded, not counted as passes or useful
timings. The export now verifies all IDs and their SQL round trip. The native
fit generates its rows directly in SQL and did not use the invalid export.

CI and practical limits
-----------------------
.github/workflows/databricks-validation.yaml and its R runner are ready for
review, with weekly/default-branch/manual triggers, required native credentials,
a pinned driver checksum, and retained artifacts. They have not been published
or run on GitHub Actions in this session. The large 5M validation is a separate
release check, not part of routine credentialed CI.

No finite suite covers every data configuration. These checks validate the
implementation and specified numerical contracts; they do not establish an
empirical model's identification or causal interpretation. Known-separation
tests are not a general separation detector. See inst/GLM-VALIDATION.txt for
supported API limits, tolerances, test scope and reproduction commands.
