Implementation/coverage
-----------------------
Native dbreg(..., retain="prediction") shares bounded portable learned-effect
state with dbglm. It fixes the fitted slopes, solves nuisance effects and checks
recovered training RSS; predictions preserve order, need no outcomes or weights,
and survive disconnect/serialization. Demean/compress/auto, factors/references,
composite/three-way/disconnected FEs, collinearity, zero weights, missing data,
typed BIGINT/adjacent-double keys, source removal, and cleanup are covered.
Mundlak retention, learned-effect intervals and oversized state explicitly error.
Default retention is none; stored compressed-cell prediction remains unchanged.

Recovery exposed and fixed pre-existing compressed-estimator precision issues:
base factor labels merged adjacent doubles; numeric DBI conversion could round
large integer FE keys; integer64 sufficient statistics truncated fractional RSS
arithmetic. Exact typed cell/cluster keys also prevent separator collisions.
Both DuckDB BIGINT modes and native ODBC validate these paths. Shared GLM tests
also cover unknown FE keys overlapping absorbed regressor factors.

The performance runner's prepare/run usage is documented at the top of
_benchmarks/check_fixest_compat_performance.R. Prepare a fresh 1,000,000-row
database; run linear_default for baseline/current and linear_prediction for
current, five measured repetitions per batch, twice sequentially. Each runner
records runtime versions, source hashes and fit values. Use /usr/bin/time -v
for process RSS. performance/summarize.R reproduces the saved comparisons.
