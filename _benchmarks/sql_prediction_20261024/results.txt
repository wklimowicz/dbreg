Behavior and coverage
----------------------
Explicit row_id plus conn/table/path or R newdata selects a dbreg_prediction
relation. Native vector defaults remain unchanged. Output is materialized once;
unique/nonmissing keys are validated on that immutable result. OLS and four
GLM link/response families use fitted coding and learned effects. Portable
state uploads only bounded dictionaries; SQL dictionaries stay in their owner.
Missing/unknown/non-estimable FE rows preserve their keys with NULL predictions;
unseen ordinary factors error. Fitted levels are never discovered from newdata.

Shared fixtures cover powers/interactions/references, arbitrary native text,
17-digit decimal factors, exact BIGINT/date tuples, nonstandard keys, portable
three-FE/varying-slope state, SQL two-FE dictionaries, missing/unseen keys,
duplicate/NULL/NaN key failures, source preservation, exports, serialization,
release and output survival after model close. Local ownership tests also cover
shared sessions across outputs/fits, released public handles, last-owner close
and garbage collection. Caller-named exports require caller-owned sessions.
Poisson response matches R's epsilon floor and remains finite at links 701/709;
actual overflow, missing inputs and Inf-Inf are checked independently.

The first native run failed before completion because the new output CTAS
bypassed dbglm_sql(), leaving isfinite() untranslated. Source/logs are preserved
under native-initial. The final path uses the existing translator. Early package
checking also exposed a missing utils::head import; the final namespace check
passes with no new dependency. These failed development runs are not passes.

Million-row resource check
--------------------------
large-output.R reuses the SQL-only paired-noise two-FE fixture with 1,000,000
rows and 50,000/49,997 FE levels. Every keyed prediction is checked in SQL against
the analytical target; max absolute error is 1.35840449999591e-10.
No training/prediction panel is collected. Instrumented output creation returns
at most one row per query, 3,744 cumulative R result-object bytes. Only the final
output relation survives; closing it restores the fitted table inventory, and
closing the model restores the original caller inventory.

Three measured warmed output creations: median 0.154999999999999 seconds;
range 0.146000000000001 to 0.510000000000002 seconds. Result handle object: 41,688 bytes.
Peak whole-process RSS: 561,276 KiB, including model fitting, embedded DuckDB,
trace instrumentation and backend execution. This is not output-only R memory.
The row-sized output remains in the database. Two DuckDB threads, 2GB limit;
other validation clients were active. These local measurements do not establish
native/disk-bound performance or Delta history/storage behavior.
