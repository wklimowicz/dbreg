Implemented behavior
---------------------
Oversized retained prediction with two FE blocks, without varying slopes, can
keep its dictionaries in SQL. Slopes stay fixed at the original fit. Alternating
projections recover nuisance effects and projections of the original expanded
regressors. A bounded within-X null system certifies regressor relations.
Graph component labels, with pointer compression, reject cross-component new
combinations. Unobserved but estimable within-component combinations remain
predictable. Recovery checks final eta or the fitted OLS RSS before transfer.

One or two FE blocks support typed composite keys. Dictionaries store original
typed key values, learned effects, regressor projections and component labels;
only requested keys and bounded slope matrices leave SQL. Mathematical state
and ownership leases remain separate. Two-FE recovery uses the fitted projection
iteration limit and min(fitted tolerance, 1e-10). Nonconvergence errors clean up.
Reusing native table names bounds the number of live row intermediates; physical
backend history/disk storage was not measured by this gate.

Existing single-FE matching now shares the bounded lookup/rank helper. FE-only
GLMs correctly handle zero-column designs in both paths. Portable small-state
and native compact defaults keep their existing behavior. Three or more large
FE blocks and varying slopes still require portable feasibility; database
prediction output, retained inference and compatibility adapters remain pending.

Large local resource fixture
-----------------------------
large-state.R generates a SQL-only million-row panel with 50,000 first-FE and
49,997 second-FE levels, two slopes and the default 2e6 prediction entry budget.
Each adjacent observation pair has identical regressors/FEs and opposite noise;
the noise is exactly orthogonal to all model columns. Thus the fitted predictor
is known analytically without collecting training rows into R.

Six measured completed fits (three per mode after one warmup) match names,
coefficients, full covariance and N. Retained predictions match the analytical
target to 1e-7. Every close restores the original table inventory.

                         compact default       retained prediction
median fit               4.588s                9.713s
peak process RSS         539,284 KiB           636,972 KiB
mathematical state       0 bytes               8,120 bytes

Retention added about 5.1s and 18% whole-process peak RSS here. DuckDB is
embedded, so RSS includes database execution memory, not just the R heap.
Instrumented two-FE recovery queries return at most one row during fitting,
with 29,472 cumulative R result-object bytes (object.size, not wire bytes).
Both dictionaries remain in SQL. Only 100 newdata rows are fetched for value
checks outside fit timing; no training panel is collected into R.

R 4.6.0, DuckDB 1.5.2; two DuckDB/BLAS/OMP threads and a 2GB DuckDB limit.
Local tests/native clients were active in the background. These warmed resource
measurements have timing variation and do not establish native or disk-bound
performance. The native fixture deliberately forces tiny transfer budgets and
many repeated predictions; its total runtime is not a per-fit latency benchmark.
