Fixest replacement implementation contract
==========================================

Branch: feat/fixest-compat, based on wojtek-dev at 00f2868.
This is a staged implementation. The checklist below distinguishes the target
from implemented behavior; it is not a claim of complete fixest compatibility.

Target and boundaries
---------------------
Provide regression-only replacements for supported feols/feglm calls on DuckDB
and native Databricks. Include OLS/LPM, binomial cloglog/logit/probit and the
existing Poisson family. The caller owns data preparation, external weights,
initializations and any EM/other outer algorithm. No outer-algorithm state or
orchestration belongs in dbreg.

Keep existing dbreg/dbglm entry points compatible. Introduce fixest-shaped
entry points for positional/named arguments and defaults rather than silently
changing native prediction defaults or OLS small-sample policies. Unsupported
arguments must fail explicitly. Do not pretend to be a fixest object: support
the agreed extraction generics with real methods and document other consumers.

Implementation sequence
-----------------------
1. Fractional observation weights and independently checked likelihood reporting.
   Implemented in this increment; validation evidence is in GLM-VALIDATION.txt.
2. Shared fitted-state contract for learned effects, sample keys and resource
   ownership. OLS/GLM now share typed-key validation and retained-key exports;
   OLS exports use an immutable snapshot throughout fitting. Bounded portable
   OLS/GLM learned-effect state is implemented behind explicit retention. Large
   single-FE dictionaries and resource leases can stay in SQL; multi-FE SQL
   recovery, database prediction outputs and post-fit scores remain pending.
3. Supported formula/argument normalization: i()/references, public coefficient
   identities, OLS offsets and varying slopes, fixef.rm, weights and subset.
   Partial existing formula support remains; compatibility entry points pending.
   Native fitting/extraction checks now reject unsupported extra statistical
   arguments, preserving explicit legacy aliases. Linear formulas no longer
   capture caller or strategy environments in compact results.
4. Fitted link/response prediction with learned effects, including estimable
   zero-weight rows, without outcomes in newdata. Implemented for bounded GLM
   OLS/GLM state with retain="prediction"; 149 native OLS checks and 118 native
   GLM checks pass. Existing compact OLS population prediction remains available.
5. Two-way OLS cluster covariance and post-fit inference on the fitted sample.
   Not implemented. Include small-sample/FE-nesting policies and test df.
6. Summary, se/coeftable, likelihood, sample and df extraction; convergence,
   persistence and large-output contracts. Existing methods cover only a subset.
7. End-to-end local/native and large-resource acceptance checks. Not complete.

Statistical contract
--------------------
Weights multiply each observation's objective and score. Zero-weight rows are
excluded from fitting, not automatically from later prediction. N is the number
of retained source observations, never the weight sum or compressed-cell count.
Changing weights between calls must recompute the eligible sample, pruning,
design identification and weighted projections; no stale weight-dependent cache.

For binary responses, fixest::feglm uses R's binomial family$aic for logLik.
With fractional weights this rounds original weights to integers, ties to even.
dbglm reports that convention through logLik(model) and standard AIC/BIC;
logLik(model, type="weighted") exposes the unrounded Bernoulli objective.
Fitting, deviance and covariance use unrounded weights in all cases. Poisson
and integer-weight binomial likelihoods are unchanged. The reference convention
was inspected and tested with fixest 0.14.0; future reference changes must be
reviewed explicitly. Never infer weight semantics from coefficient parity alone.

Compare ordinary fixest default calls as well as explicitly aligned policies.
In particular, fixef.rm="none" tests do not establish default sample parity.
Keep model df, covariance correction K and inference df distinct. Match the full
covariance and named coefficient table, including off-diagonal entries.

Fitted-state design requirements (partially implemented)
-------------------------------------------------------
Retain the original formula and fitted design coding separately from SQL aliases;
retain FE key dictionaries, slopes, learned coefficients and centering metadata.
Recovery must work on both bounded and SQL fallback solvers. Prediction must be
invariant to other rows/outcomes in the supplied prediction batch. Individual
FE coefficients need a normalization; unidentified new combinations across
disconnected components must not produce arbitrary predictions.

Use stable source keys for retained-row information and database output. A SQL
relation has no implicit row order. In-memory predictions preserve input order,
including missing/nonestimable positions. Database predictions return a keyed
relation or write to a caller-selected destination; full collection is explicit.
Distinguish fitting-sample predictions, original-sample alignment and newdata
prediction, including the behavior of observations excluded only by zero weight.

Small FE dictionaries may be portable R state. Large dictionaries and retained
sample/score state may require owned database relations with explicit release
and export/reopen behavior. Newdata prediction need not retain training outcomes;
post-estimation clustering needs sufficient state for the original fitted sample.
Source mutation must not silently change an existing fit. Define behavior after
disconnect, serialization and cleanup; do not serialize live connection pointers
as though they were durable model state.

Validation gates
----------------
Use fixest as the primary oracle, independently refined where needed; never warm
the reference from dbreg estimates. Compare exact retained IDs and term names,
full covariance, SEs/tests/CIs, likelihood/objective, N, df and predictions. Use
explicit absolute-plus-relative tolerances, and investigate unstable references.
Check small explicit-dummy fits and analytic objectives/information separately.

Fixtures cover multiple seeds, rare events, missing/zero/tiny weights, successive
weight changes, offsets, factors, interactions, varying slopes, composite FEs,
singleton chains, separation, collinearity and disconnected FE graphs. Include
row permutation, FE relabeling, unit changes and independent weight-rescaling
checks. Test forced solver fallbacks and cleanup after failed fits.

Run shared fixtures on DuckDB and native Databricks, plus the existing OLS/IV
suite. Native skip or missing credentials is not a successful backend check.
Large release checks measure client RSS, transfer size, database memory/storage,
query count, prediction output and repeated-call resource growth. Respect the
existing compact FE-transfer follow-up in TODO.md; performance evidence must
identify source revisions, input generators and actual completed fits.

Decisions for the next increment (design, not implemented API)
------------------------------------------------------------
Follow dbreg's existing implementation, naming and resource conventions. Use
fixest to resolve user-facing compatibility questions when dbreg has no existing
contract; do not copy fixest's internal object structure or numerical engine.
The executable numerical reference remains installed fixest 0.14.0. The adjacent
fixest source checkout can be newer, so identify its revision separately.

Entry points: add dbreg::feols(fml, data, ...) and dbreg::feglm(fml, data, ...).
Keep native dbreg()/dbglm() defaults and argument order. Database binding uses
the existing named conn/table/path arguments, with data optional for that form.
Require exactly one adapter data source, rather than silently picking among
conflicting bindings. Explicit namespace use avoids masking ambiguity.

Adapters accept weights/offsets as a column name or one-sided column formula.
For in-memory data only, numeric vectors align to original input positions
before any filtering and must have exactly nrow(data) elements. Database inputs
require columns; externally prepared vectors must be joined by explicit keys
by the caller. Never attach a vector using database fetch order. Start subset
support with logical in-memory vectors and documented SQL-compatible forms;
reject other expressions until their semantics are implemented and tested.

Use fixest's response prediction default in adapters. Resolve supported family
strings through the existing built-in family validator: "binomial" means logit,
"poisson" means log, and cloglog/probit require an explicit binomial family.
The fixest-shaped feglm default is Gaussian identity and must route through the
OLS compatibility engine with reference-checked extraction/inference. Until
that route exists, reject it explicitly; do not substitute binomial cloglog.
Identical Gaussian slopes do not establish equivalence: fixest's Gaussian
feglm likelihood and covariance conventions differ from feols and need their
own reference fixtures before enabling this route.

Register real extraction methods, including fixest's se/coeftable generics when
available, without a fixest class or an Imports dependency. At each increment,
publish a support table covering fitting AND methods; unsupported post-fit
arguments must error, including cluster/ssc requests in lean objects. Default
and explicitly aligned statistical policies need distinct reference fixtures.

Internal state is a versioned list named fitted_state shared by OLS and GLM.
Keep mathematical state as values; use a separate resource environment only
for connection/table ownership and explicit release. Proposed list sections:

  specification: original formula, fitted model_spec, public/internal names,
    retained/dropped basis, factor sources/levels/references, intercept, offset,
    FE component columns and varying-slope coding.
  coefficients: slopes, centers, learned FE coefficients and solver-specific
    normalization corrections. Store an estimability representation as well as
    coefficients; known marginal levels alone do not identify new combinations.
  sample: original/eligible/retained counts, validated typed key columns,
    in-memory input positions when applicable, exclusions and immutable keys.
  inference: bread and the immutable fitted rows/score inputs required for
    supported post-fit covariance. Store original weight units and the fitting
    scale separately. New cluster data require a validated one-to-one key map.
  resources: backend, owned relations, connection ownership, release status,
    storage schema version, and advertised portable/live capabilities.

Retain current compact native defaults. The adapter default retains the state
needed by its advertised methods; a lean adapter deliberately discards state
and errors for methods that require it. Do not add retained database resources
to the current native default as an accidental side effect of adapters.

In-memory input gets an original-position key before filtering. A database
caller supplies nonmissing unique row_id columns (including composite/integer64
keys) whenever stable external alignment is required. An internally generated
key is valid only inside its owned materialized snapshot, never as a reusable
identity on the source relation. Database prediction returns caller keys; an
unkeyed output may only promise identity inside its own materialized output.

Materialize inference/sample state before releasing fit-owned relations. Copy
only required columns, and never retain a source query that changes with later
writes. Bounded FE dictionaries may live in R; exceeding a declared transfer
budget selects owned database dictionaries, never an unbounded fetch. Retained
state must use typed source keys, not only temporary dense ranks.

Portable dictionaries support newdata prediction after disconnect/saveRDS.
Database-backed state requires its live owning session until an explicit export
is implemented. A disconnected or deserialized invalid handle must error before
SQL execution; it cannot silently refit or reread the original source. Release
is idempotent and affects only that model's owned relations; caller connections
and explicit sample/prediction exports remain caller-owned. Unsupported export/
reopen operations remain explicit errors until backed by tested storage logic.

Observation-identity foundation: native OLS now accepts the existing GLM names
row_id/sample_table. OLS exports require explicit keys and a caller connection;
they reject sql_only/data_only, copy required source columns once into an owned
fit snapshot, and export retained typed tuples without collecting them into R.
Source-key validation precedes filtering and compares counts in SQL. Private
snapshots are released on success/error; caller-owned exports survive the fit
and last for their database session. Collect BIGINT keys using an integer64
DBI conversion setting. No inference method silently rereads these exports.

DuckDB and native Databricks support these exports. Databricks creates scoped
column mapping on new snapshot/export tables only when their names require it;
it never changes a caller table or warehouse setting. Native SHOW TABLES checks
existing exports because ODBC's catalog metadata can omit session tables.
An export never replaces an existing relation. Explicit snapshots cost database
storage for required source columns plus the retained-key output; default native
fits do not retain these resources. This is not portable fitted-state persistence.

The 2026-10-24 million-row DuckDB performance checkpoint found no large consistent
normal-fit regression (pooled integer-weight medians within roughly -6%/+7%).
Explicit key/export modes cost 2.13x for simple OLS, 1.61x for two-FE OLS and
1.04x-1.29x for cloglog in that fixture; peak client RSS rose about 16% with
exports. Fractional binomial reporting added a measured 0.047-0.079s SQL pass.
These are local warmed measurements, not native or disk-bound guarantees.
Evidence: _benchmarks/compat_performance_20261024. Keep prediction dictionaries
separate from optional observation-sized inference state and reuse existing
fit-owned relations when retention is requested; default native fits stay compact.

Portable prediction slice (validated on both engines): native dbglm now accepts
retain=c("none", "prediction"), defaulting to the existing compact behavior.
Prediction retention reconstructs the learned predictor from bounded joint
FE/regressor moments on both moment and SQL fitting paths, including varying
slopes. Recovery must reproduce the fit's final eta before any fit-owned table
is released. State is a versioned plain list, without resource handles, rows,
outcomes or fitting weights. It does not provide training-row/default prediction
or post-fit covariance. The single-FE database-backed extension follows below.

Typed dictionaries preserve BIGINT text exactly and encode double keys with
17 significant digits, including composite tuples. Supported SQL key types are
integer, double/float, character, logical and date; unsupported types error.
Integer newdata above 2^53 requires integer64 or exact decimal strings.
Unknown keys, missing inputs and rows outside the joint identified design span
return NA. Null directions certify disconnected components and training-only
regressor relations; marginal level membership is insufficient. Unseen ordinary
regressor factor levels keep the existing explicit error behavior.

Portable recovery is limited by dbreg.prediction_max_entries (default 2e6), the
FE moment row limit, and the existing dense/cross-product feasibility gates.
The limits bound transfers and dense/null matrices. Oversized single-FE
requests without varying slopes select owned database state when the bounded
slope system fits the budget. Other oversized requests error and clean up;
large multi-FE/varying-slope recovery remains required by the full target above. Dictionary creation
adds explicit SQL work; native default fitting does not create these dictionaries.

Tiny group-specific weights require a relative group-equation certificate as
well as square-root-information scores. The existing aggregate query supplies
both scales. FE nuisance right-hand sides are projected in information-scaled
coordinates so SQL roundoff from a large group cannot swamp a small group's
equation. Uniformly small original weights continue to use the earlier global
power-of-two normalization. Keep this numerical safeguard when extending state.

Portable OLS prediction checkpoint (2026-10-24): dbreg accepts the same explicit
retain="prediction" option for exact demean/compress/auto fits. Recovery fixes
the original fitted slope vector and solves only for nuisance effects, checking
training RSS before releasing the immutable frame. It preserves row order and
missing/nonestimable positions, needs no outcomes/weights in newdata, and works
after serialization/disconnection. No-FE fits use the existing compact predictor.
Mundlak retention and learned-FE prediction intervals explicitly error. Existing
stored compressed-cell predictions remain available through the native API.

Compression preserves exact double/BIGINT FE identities and typed cluster-cell
matching. Only known sufficient statistics are converted from integer64 before
fractional arithmetic; identifier columns retain their exact representation.
Full local gate: 4,087 assertions. Native OLS: 149; native GLM: 118 plus three
snapshot checks (see source-scope caveat in GLM-VALIDATION.txt). Million-row
benchmarks show no substantial default regression; explicit retained prediction
costs 0.171s to 0.422s for two-FE OLS and 0.0255s to 0.1865s for compressed OLS
in this warmed local fixture. Evidence: _benchmarks/linear_prediction_20261024.

Database-backed single-FE prediction (2026-10-24)
------------------------------------------------
When portable recovery exceeds its budget, one absorbed FE (including a typed
composite key) without varying slopes can retain its dictionary in SQL. The
original fitted slopes stay fixed. Weighted group residual means recover the
learned effect; a bounded within-X Gram/null system checks new-row estimability.
Recovery certifies the fitted predictor or OLS RSS before any source is released.
Only requested prediction keys are queried, in bounded batches. Typed joins
preserve integer text, nearby doubles, arbitrary strings, dates and logical keys;
native text keys use the existing bounded JSON transport to preserve quoting.
No outcomes, fitting weights or source query are needed for later prediction.

Mathematical state and resource ownership remain separate: fitted_state contains
values and table metadata; resource_state is a versioned environment lease with
a namespace finalizer. close(model) drops only that lease's owned tables, is
idempotent, and leaves caller connections/explicit exports intact. Copies share
the lease. A model-owned connection closes after its last model/output lease;
failed drops remain tracked and retryable. Garbage collection attempts cleanup.
Prediction checks the live handle before SQL; saved/reloaded or disconnected
handles cannot reconnect, refit, or silently reread mutable source data.
Portable small dictionaries retain their existing disconnect/saveRDS behavior.

This implements single-FE database dictionaries and in-memory newdata matching.
Database newdata/keyed output relations, large multi-FE/varying-slope state and
post-fit inference remain pending. Resource sharing for future output relations
is tested internally; this checkpoint does not expose a database output API.
